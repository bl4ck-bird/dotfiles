# Roadmap Criteria

성과는 사용자·운영자가 확인할 수 있는 결과이며 반드시 릴리스나 일정 단위는 아니다. 각 항목의 범위·요구·완료 근거·선행 조건·위험·순서 이유를 정한다.

성과 하나로 완료할 요구와 후속 작업에서도 계속 지킬 공통 제약을 구분한다. 공통 제약은 특정 성과의 완료로 종료하지 않으며 영향받는 후속 명세·계획에 전달한다.

## Ordering

필수 의존성을 지키고 가능한 후보 중 핵심 가치를 일찍 검증하며 큰 위험을 해소할 순서를 선택한다. 기반 작업도 가능하게 할 결과와 검증이 있어야 한다. 가까운 작업만 상세화하고 먼 작업의 불확실성을 보존한다.

## Changes and Completion

검증된 진행 사실·링크는 바로 갱신한다. 성과 추가·제외·우선순위·수용 범위 변경은 이유·전후 차이·후속 작업 영향을 사용자와 검토한다. 승인 범위의 태스크 순서 조정을 로드맵 재승인으로 확대하지 않는다.

작업 완료 수와 마일스톤 수용 조건의 충족을 구분한다. 통합 흐름·필수 사용자 확인이 남으면 완료로 기록하지 않는다. 실제 기한과 근거 있는 추정을 구분하고 순서 변경으로 식별자를 바꾸지 않는다.

## Handoff

필수 리뷰와 사용자 승인 후 다음 상세 명세에 결과·범위·요구·공유 구조·선행 조건·완료 근거·미결정을 넘긴다. 로드맵 승인은 구현 승인이 아니다.
