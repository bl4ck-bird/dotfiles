# Approval and Evidence

## Review Target

- 문서 검토·승인 기록을 만들거나 재개할 때 [승인 기록](approval-records.md)을 읽고 필수 정보와 후속 지시를 확인한다.
- 리뷰 전에 관련 문서 묶음의 경로·내용 해시·사본을 보존한다. 사용자 승인은 해당 대상·범위·응답과 연결한다. 응답 위치를 확인할 수 없으면 그 한계를 기록한다.
- 해시·문서의 승인 표시·리뷰 통과는 사용자 승인 자체가 아니다. 검토 권한·설계 승인·구현 권한·외부 작업 권한을 구분한다.
- 검토·승인 시점의 대상만 보존하며 매 편집마다 저장소 전체를 복사하지 않는다. 과거 기록을 변경한 문서의 새 승인으로 바꾸지 않는다.

## Continued Authorization

| Change | Treatment |
| --- | --- |
| 의미를 보존한 표현·링크 수정 | 비교 근거를 남기고 기존 승인 적용 |
| 검증된 구현 사실 갱신 | 실제 결과를 확인해 기존 승인 적용 |
| 위임된 내부 선택 | 승인된 제약 안에서 검증하며 진행 |
| 동작·구조·데이터·수용 기준·범위·권한 변경 | 관련 실행을 보류하고 필요한 리뷰·사용자 승인 |

메인 에이전트가 변경의 의미를 판단한다. 변경량이나 주 문서의 해시만으로 판단하지 않고 관련 참조의 가정도 확인한다. 기존 작업 기록에 적용 범위·이유·비교 근거를 남기며, 사소한 수정마다 새 승인 파일을 만들지 않는다.

코드에 맞춰 명세를 고치는 것이 항상 사실 갱신은 아니다. 승인된 동작과 다르면 구현 결함인지 요구 변경인지 먼저 판단한다. 기술적 재리뷰가 필요하다는 이유만으로 사용자 승인을 다시 요구하지 않는다.

## Verification Target

- 코드 대상을 보존하거나 검증·근거 재사용을 판단하기 전에 [검증 기록과 유효성](verification.md)을 읽는다.
- 검증 대상은 기준 커밋과 실제 변경 내용으로 식별한다. staged·unstaged·신규 파일을 포함하고, 커밋 없는 대상도 누락하지 않는다.
- 명령·환경·실행 결과·한계를 실제 대상과 연결한다. 관련 코드·환경이 바뀌면 영향을 받는 검증을 다시 수행한다.
- 결과는 실행별로 보존하고 요약의 완료 표시나 브랜치 이름만 믿지 않는다. 실패·건너뜀·미발견·실행기 오류를 구분한다.

## Gate Exceptions

검사 생략은 해당 예외의 사용자 승인 또는 승인된 계획이 필요하다. 생략한 검사·이유·위험·보완 검증·후속/만료 조건을 기록한다. 예외는 검사 통과나 비밀정보·권한 보호 해제를 뜻하지 않는다.

## Resumption

현재 상태·승인 대상·관련 리뷰·실제 변경을 대조한다. 유효한 승인과 근거는 재사용하고 필요한 차이만 조사한다. 실행 종료 여부는 [실행 상태 규칙](../../harness-execute/references/runtime.md)에 따라 별도로 확인한다.
