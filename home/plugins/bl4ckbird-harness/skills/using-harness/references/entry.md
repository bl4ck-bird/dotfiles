# Entry and Routing

## Activation

프로젝트 설정은 `.harness/config.toml`이다. 두 필드는 필수이며, 스키마 버전은 정수 `1`, 활성화 값은 불리언이다.

```toml
schema_version = 1
enabled = true
```

| Configuration State | Action |
| --- | --- |
| 없음·비활성 | 자동 진입하지 않고 기존 기록 보존 |
| 유효·활성 | 요청·승인·실제 상태를 확인해 단계 선택 |
| 문법 오류·필드 누락·타입 오류 | 위치와 원인을 보고하고 관련 실행 보류 |
| 미지원 버전·알 수 없는 필드 | 임의 무시·변환 없이 호환성 문제 보고 |

개별 스킬의 명시적 호출은 자동 활성화 없이 가능하다. 해당 스킬의 필수 조건은 확인하며 설정을 조용히 바꾸거나 게이트를 우회하지 않는다.

비활성 프로젝트의 단일 호출에는 프로젝트 진행 기록 갱신을 자동 요구하지 않는다. 질문·읽기 전용 검토처럼 답변으로 처리할 수 있는 요청은 초기화 없이 진행한다. 파일 산출이 필요한 작업에는 [저장 경계](storage.md)를 적용한다.

## Project Root

1. 명시된 프로젝트·작업 경로가 실제 대상인지 확인한다.
2. 명시 경로가 없으면 현재 Git 워크트리 루트를 사용한다. 하위 패키지마다 초기화하지 않는다.
3. Git이 없으면 지정 프로젝트 또는 세션 작업공간을 사용한다. 대상이 불명확할 때만 묻는다.
4. 중첩 저장소·서브모듈은 바깥 프로젝트의 활성화를 자동 상속하지 않는다.

코드 경로와 기록의 기준 경로가 다른 워크트리는 배정 정보·기존 기록으로 관계를 확인한다. 관계를 알 수 없으면 새 기록 저장소를 만들지 않고 [워크트리 규칙](../../harness-execute/references/worktrees.md)을 따른다.

## Setup

프로젝트 초기화·지속 활성화를 명시적으로 요청할 때만 수행한다. 진입 스킬을 읽거나 단일 작업에 적용하라는 요청으로 설정·제외 규칙을 생성하지 않는다.

1. 기존 `.harness/`와 Git 추적 여부를 확인한다.
2. 루트 `/.harness/` 제외 규칙을 확인·추가한다. 이미 추적 중인 기록은 별도 이관 대상으로 보고하며 임의로 추적 해제하거나 Git을 초기화하지 않는다.
3. 없는 `CONTEXT.md`·`CURRENT.md`만 최소 내용으로 만든다.
4. 준비가 끝나면 활성 설정을 기록한다. 기존 문서·승인·완료 상태를 덮어쓰거나 만들어내지 않는다.

설치만으로 프로젝트 아키텍처·로드맵·명세를 생성하지 않는다. 각 단계가 내용을 결정할 때 [문서 저장 규칙](storage.md)에 따라 작성한다.

## Proportional Work

기대 결과·수용 기준·실행 경로·영향·검증 방법이 명확하고 중요한 미결정이 없는 되돌리기 쉬운 작업은 명세·계획을 한 문서로 줄일 수 있다. 두 책임과 리뷰·승인을 유지한다.

파일 수로 경로를 선택하지 않는다. 오탈자·링크 등 동작과 중요한 결정을 바꾸지 않는 명시적 수정은 직접 수행·검증한다. 새 동작 결정이 필요하면 해당 설계로 돌아간다. 전체 세션을 고정된 경로에 묶거나 기록 부재를 새 프로젝트의 증거로 삼지 않는다.
