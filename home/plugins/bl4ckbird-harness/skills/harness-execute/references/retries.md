# Correction Limits

이 규칙은 구현 결함의 수정에 적용하며 구현 전 설계 결정을 자율 변경하는 권한을 부여하지 않는다.

- 같은 문제는 위반 계약·재현 조건·원인으로 식별한다. 원인이 없으면 같은 증상의 연속성을 유지한다.
- 한 수정 시도는 하나의 수정 가설을 적용하고 검증한 단위다. 편집 횟수·명령 재실행 횟수와 구분한다.
- 같은 문제에서 두 번 실패하면 진단한다. 새 근거와 구체적으로 다른 승인 범위 접근이 있을 때만 한 번 더 시도한다. 문제당 총 세 번이 한도다.
- 최초 구현·리뷰 이후 슬라이스당 수정 라운드는 최대 다섯 번이다. 한 라운드는 여러 지적 사항을 다룰 수 있다. 문제·슬라이스 한도를 함께 적용한다.
- 로컬 검증에서 실패한 수정도 시도에 포함한다. 예상한 최초 TDD 실패는 결함 수정 실패로 세지 않는다.
- 진단·모델·에이전트·세션·최종 검사로 한도를 초기화하지 않는다. 중단은 자동 실패가 아니지만 실행 여부를 확인할 때까지 남은 시도를 예약 상태로 유지한다.
- 한도에 도달하면 관련 작업을 보류하고 문제·시도·결과·영향·다음 제안을 보고한다. 한도 소진을 결함 수용·완료로 처리하지 않는다.

호출 거절·서비스 오류의 복구는 [호출·자원 규칙](resources.md)을 따르며 실제 구현 수정 시도와 구분한다.
