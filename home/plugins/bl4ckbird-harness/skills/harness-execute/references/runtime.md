# Execution State and Recovery

## Ownership and Records

배정·기록 갱신·복원 전에 [상태와 근거 기록](state-records.md)의 필드 의미·배정/시도 구분·상태 판정·카운터 규칙을 읽는다.

메인 에이전트가 작업별 단일 `state.json`의 현재 단계·슬라이스/태스크 상태·차단 사유·승인/호출/근거 참조를 관리한다. `CURRENT.md`는 탐색용 요약이다. 구현 에이전트·리뷰어는 자기 결과를 보고하며 공유 상태를 확정하지 않는다.

상세 호출·시도·검증·판단은 별도 기록에 보존하고 상태 파일에 전체 로그를 넣지 않는다. 새 호출·시도 기록은 [식별자 발급 규칙](../../using-harness/references/identifiers.md)을 따른다.

## Publication

1. 호출 의도와 필요한 수정 시도 예약을 보존하고 기록 성공을 확인한다.
2. 호출 후 실제 호스트 식별자를 연결한다.
3. 실제 결과·검증·처리 판단을 보존한 뒤 현재 상태를 갱신한다.
4. `CURRENT.md`를 갱신한다.

상태는 대상 디렉터리의 임시 파일에 작성·검증·동기화한 뒤 원자적으로 교체한다. 현재 상태가 예상 입력과 다르면 먼저 대조한다. 보존 기록은 새 ID로 발행하고 기존 기록을 덮어쓰지 않는다. 호스트 호출과 파일 갱신이 하나의 트랜잭션이라고 주장하지 않는다.

이 절차는 [기록 도구](../../using-harness/references/record-tools.md)의 명령과 지원 스키마로 수행한다. 필요한 기록 도구가 없거나 현재 기록을 읽을 수 없으면 관련 배정·상태 변경을 보류하고 부족한 기능을 보고한다. 임의 스키마나 수동 반복으로 복구 보장을 만들어내지 않는다.

공용 도구는 ID 할당·구조/참조 검사·대상 비교·기록 게시와 복구를 처리한다. 단계 선택·승인 의미·근거 충분성은 메인 에이전트가 판단하고 에이전트 호출은 호스트 도구로 수행한다. 공용 도구가 에이전트를 실행하거나 별도 진행 엔진이 되지 않는다. 검사 통과는 사용자 승인이나 호스트의 권한 허용을 대신하지 않으며 도구 밖 호출까지 강제 차단한다고 주장하지 않는다.

## Reconciliation

| Observed State | Action |
| --- | --- |
| 결과 존재·상태 지연 | 실행 종료와 검증 대상 유효성을 따로 확인해 누락된 상태만 갱신 |
| 실행 종료·보고 없음 | 실제 변경과 남은 검사·리뷰를 확인. 처음부터 재구현하지 않음 |
| 완료 표시·근거 부족 | 미검증으로 남기고 필요한 자료 복구 |
| 이전 실행 진행 중 | 추적하며 충돌하는 작업 배정 금지 |
| 실행 여부 불명 | `needs_reconciliation` 유지, 충돌할 변경·외부 작업 보류 |
| 상태 손상·충돌 | 기존 자료 보존 후 입증된 사실만 복원 |

사용 가능한 결과와 실제 실행 종료를 구분한다. 종료된 에이전트 턴에도 백그라운드 명령이 남을 수 있다. 시간 경과·ID 부재·연결 끊김·파일 변화 없음·중단 요청만으로 종료를 확정하지 않는다.

활성 작업의 기록·Git 변경을 먼저 대조하고, 관련 실행이 남아 있을 징후가 있으면 해당 로컬 명령·프로세스·외부 효과를 확인한다. 필요한 사실을 확인할 수 없을 때만 보류 범위와 부족한 근거를 사용자에게 알린다. 일반적인 진행 승인은 실행 종료의 근거가 아니다.

## Resume and End

`CURRENT.md`, 활성 명세·계획·최근 검증, 활성 작업의 상태·미완료 배정·재시도 근거와 Git 상태에서 이어 간다. 과거 세션 전체 탐색이나 이전 에이전트 식별자 복원을 요구하지 않는다.

근거를 다시 읽거나 세션이 바뀌어도 호출·수정 횟수를 초기화하지 않는다. 상태가 없거나 모순되면 충돌할 작업을 보류하고 필요한 로컬 근거만 대조한다. 불확실한 배포·마이그레이션은 결과 확인 없이 반복하지 않는다. 종료 전 실제 상태·결과·미결정·다음 행동을 보존한다.
