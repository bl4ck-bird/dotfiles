# State and Evidence Records

## Current State

작업의 `.harness/work/<work-id>/state.json`만 현재 실행 상태를 소유한다. 생성·복원·배정·상태 변경 전에 이 의미 규칙과 [기록 도구](../../using-harness/references/record-tools.md)를 적용한다. 중첩 필드는 `schema state`로 확인하고 임의 형식으로 실행하지 않는다.

| Field | Meaning |
| --- | --- |
| `schema_version`, `work_id`, `revision` | 지원 형식·작업·상태 갱신 번호 |
| 현재 단계·`approval_refs` | 진행 단계와 적용되는 승인 근거 |
| 슬라이스·태스크 항목 | 간결한 진행 상태·최종 통합 검증 참조·리뷰 판정/대상·미해결 지적 사항 |
| `active_dispatch_refs` | 실행 중이거나 결과 대조가 필요한 배정 |
| `blockers`, `finish_ref` | 보류 범위·이유·해결 행동·근거, 최종 검증/전달 기록 |

태스크 상태는 `pending` / `running` / `needs_reconciliation` / `blocked` / `completed`다. `completed`는 메인 에이전트가 태스크 결과와 필수 검증을 확인한 상태다. 구현 에이전트의 `Completed` 보고와 구분한다. 모든 태스크가 끝나도 필수 리뷰가 남으면 슬라이스 수용은 완료되지 않는다.

계획의 작업 내용·의존성·수용 기준과 상세 로그는 복제하지 않고 참조한다. 상태 요약과 `CURRENT.md`가 다르면 근거에서 복원하며, 탐색 문서를 두 번째 실행 상태로 쓰지 않는다.

## Dispatches and Attempts

- `dispatch`와 `attempt`는 각각 자기 `record_id`로 식별한다. 전자는 구현·검증·리뷰 배정, 후자는 하나의 수정 가설을 적용하고 검증한 시도이며 서로 대체하지 않는다.
- 중단 후 새 배정으로 같은 시도를 이어갈 수 있다. 같은 가설의 남은 검증은 기존 시도, 새 수정 가설의 적용은 새 시도다. 호출만 실패하고 수정이 시작되지 않았다면 수정 시도를 만들지 않는다.
- 배정에는 작업·현재 단계·역할·대상 태스크(해당 시)·실행 경로·입력 대상·호스트 실행 ID·보고 위치를 연결한다. 구현 전 리뷰는 현재 검토 범위·권한·모델 선택을 기록하며 미래 태스크·슬라이스·구현 승인을 만들지 않는다.
- 수정 시도에는 문제·가설·시작 코드 상태·관련 배정·변경·검증·결과를 연결한다. 결과를 확인해 해결·실패·중단과 다음 행동을 기록한다.

## Findings and Counters

리뷰 지적 사항은 특정 리뷰의 관찰이고, 문제는 계속 추적할 결함이다. 같은 결함의 후속 지적 사항은 기존 문제에 연결한다.

| Record | Responsibility |
| --- | --- |
| 리뷰 | 원래 지적 사항·심각도·근거 |
| 메인 에이전트의 처리 판단 | 유효성·오탐 반증·해결 상태 |
| 수정 시도 | 수정 가설·실제 결과 |
| 슬라이스 수정 라운드 | 해당 문제·시도 연결 |

[수정 한도](retries.md)는 고유 배정·시도·라운드 기록에서 계산한다. 요약 숫자가 다르면 근거와 대조하며 숫자 편집·재조회·상태 재발행으로 한도를 늘리거나 초기화하지 않는다. 중단된 시도는 실제 실행을 확인할 때까지 예약을 유지한다.

## Publication and Recovery

메인 에이전트가 배정 등록과 공유 상태 갱신을 순차 처리한다. `revision`은 낡은 입력의 탐지 수단이며 동시 실행 방지 장치가 아니다. 상태 손상·미지원 형식이면 원본을 보존하고 영향받는 배정을 보류한다. 새 빈 상태로 진행·횟수를 지우지 않는다.

[게시·복구 절차](runtime.md)에 따라 근거를 먼저 보존하고 검증된 상태만 원자적으로 교체한다. 작성 중 임시 파일은 유효한 기록이 아니다. 복구 목표는 세션·프로세스 중단이며 정전 시 무손실 복구를 보장하지 않는다.
