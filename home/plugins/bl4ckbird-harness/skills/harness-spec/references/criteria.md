# Specification Criteria

상세 명세는 구현자가 중요한 동작을 새로 정하지 않아도 되는 수준의 결과를 정의한다. 구현 순서와 명령은 구현 계획이 맡는다.

## Acceptance

사전 조건·행동·기대 결과를 연결한다. 중요한 실패에는 남는 상태·사용자 결과·재시도·취소·복구 허용 여부를 정한다. 모든 입력 조합을 나열하지 않고 중요한 불변식과 회귀 위험을 검증할 수 있게 한다.

수용 기준을 자동 검사·통합 검증·사용자 판단 등 필요한 근거 종류와 연결한다. 구체적인 명령과 테스트 위치는 구현 계획에서 확인한다.

## Decisions

확정 계약·위임된 내부 선택·미결정을 구분한다. “적절히 처리”는 재량의 범위가 아니다. 허용한 선택과 보존할 불변식을 명시한다. 중요한 동작을 바꿀 질문이 남으면 해당 실행 계획을 확정하지 않는다.

관련 없는 미래 질문은 범위 밖으로 남긴다. 승인된 공유 계약을 복제하거나 계획에서 발견한 요구 변경을 조용히 명세에 반영하지 않는다.

## Handoff

필수 리뷰와 사용자 승인 후 검토 대상 버전·수용 기준·공유 계약·재량을 계획에 넘긴다. 축약 작업은 명세와 계획을 구분해 한 문서에서 함께 검토·승인할 수 있다. 명세 승인만으로 구현하지 않는다.
