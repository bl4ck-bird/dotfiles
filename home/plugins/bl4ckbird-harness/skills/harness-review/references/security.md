# Security Review

## Triggers and Checks

| Trigger | Check |
| --- | --- |
| 인증·인가·세션 | 누가 어떤 자원에 어떤 행동을 할 수 있는지 실제 경계에서 검사하는가 |
| 외부 입력·파일·명령·URL | 쿼리·명령·경로·외부 요청에 도달할 때 입력 제약이 유지되는가 |
| 민감 데이터·키 | 응답·오류·로그·저장·외부 전달이 허용된 목적·대상을 넘지 않는가 |
| 삭제·덮어쓰기·복원 | 승인된 대상·범위를 제한하며 실패·중단 시 데이터 상태가 명확한가 |
| 외부 연동·의존성·실행 설정 | 권한·데이터 전송·코드 실행·노출 경계가 변하는가 |
| 암호·서명·키 관리 | 확립된 방식과 검증한 1차 자료·프로젝트 제약을 따르는가 |

## Evidence

관련 진입점→권한 확인→입력 처리→데이터 접근→출력을 추적한다. 필요한 호출자와 설정은 diff 밖도 확인한다. 허용 경로의 성공만으로 거부 경로가 검증됐다고 판단하지 않는다.

설계는 신뢰·보호 데이터 경계, 명세는 허용/거부 동작, 계획은 검증, 구현 리뷰·완료는 실제 결과를 확인한다. 해당 변경의 위험에 맞는 깊이를 선택하고 단어·파일명만으로 전체 보안 감사를 요구하지 않는다.

비밀정보 값을 보고·로그·리뷰 입력에 노출하지 않는다. 기존 독립 리뷰에 필요한 질문을 포함하며 별도 승인 체계·재시도 횟수·보안 단계를 만들지 않는다. 권한·데이터 처리의 요구 변경은 사용자와 검토한다.
