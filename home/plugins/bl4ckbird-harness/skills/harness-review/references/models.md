# Model Selection

## Selection

[모델 매핑](model-routing.toml)은 초기 선택 기준이다. 실제 호스트의 모델·추론 수준·권한을 호출 전에 확인한다. 능력 확인만을 위해 불필요한 유료 시험 호출을 만들지 않는다.

가벼운 기계적 확인, 일반 구현/리뷰, 복잡한 모듈 간 추론, 시스템 설계·중요 보안/손실 판단을 구분한다. 역할 이름·확신도·발견 개수만으로 선택하지 않는다. 메인 에이전트의 모델을 태스크마다 바꾸지 않는다.

작은 수정도 영향이 크면 일반·고위험 판단으로 분류한다. `xhigh` 이상은 어려운 쟁점이 정당화할 때만 사용하며 보편적인 리뷰 기본값으로 삼지 않는다. 모델을 명시할 때는 독립 배정 자료를 사용하고, 전체 이력 상속과 모델 덮어쓰기를 함께 지원하는지 실제 인터페이스에서 확인한다.

## Escalation and Replacement

근거가 부족하면 먼저 수집한다. 남은 추론 문제·상충하는 근거·새 고위험 범위가 있으면 해당 쟁점의 추론 수준이나 모델을 높일 수 있다. 모든 완료 작업에 최고 성능 재리뷰를 추가하지 않는다.

모델 사용 불가는 최초 선택 모델에 대해 매핑의 한 단계 대체만 허용하며 같은 추론 수준을 유지한다. 대체를 연쇄 적용하지 않고, 답변 불만족이나 추론 부족의 승격과 구분한다. 복구 호출 횟수는 [호출 규칙](../../harness-execute/references/resources.md)을 따른다. Astra의 자동 대체는 없으며 적합한 대체가 없으면 관련 검토를 보류한다. 고위험 리뷰를 조용히 낮추지 않는다.

선택 모델·추론 수준·이유·대체 이유를 작업/단계 기록에 남긴다. 요청 값과 실제 적용 값을 구분하며 호스트가 실제 값을 제공하지 않으면 확인 불가로 표시한다. 역할 설정이 선택값을 덮어쓰는지 확인한다.

동일 모델의 다른 리뷰어도 독립 검토를 할 수 있다. 모델을 바꾸었다고 작성자의 자기 검토가 독립 리뷰가 되지는 않는다. 매핑은 관측으로 보정할 가설이며 성능 보장이 아니다.

## Configuration Identity

구현·진단·리뷰는 같은 `model-routing.toml`을 참조한다. 이 파일은 하네스가 해석하는 매핑이며 호스트 설정으로 자동 적용되지 않는다. 역할 정의가 모델·추론 수준을 고정해 라우팅 선택을 덮어쓰지 않게 한다.

`schema_version`은 형식 버전이다. 실행 기록에는 실제 사용한 매핑 내용의 버전도 배포 버전이나 파일 내용 해시로 식별하고 선택 모델·추론 수준을 연결한다. 형식 버전만으로 서로 다른 매핑 내용을 같은 버전으로 취급하거나 프로젝트에 경쟁하는 매핑 정본을 복사하지 않는다.
