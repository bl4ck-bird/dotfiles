# Review Contract

## Independence and Inputs

작성자와 다른 리뷰어가 실제 대상·요구·제약·근거를 확인한다. 리뷰 권한·검토 대상 승인·구현 권한을 구분한다. 현재 단계의 자료로 시작하며 의도적으로 미룬 미래 산출물을 필수 입력으로 만들지 않는다.

리뷰어는 대상 수정·추가 호출 없이 허용된 검증과 자기 보고를 맡는다. 배정·공유 상태 갱신은 메인 에이전트 책임이다. 작성자의 보고는 실제 대상·검증 결과를 대체하지 않는다.

## Quality Gates

각 필수 검사의 적용 이유·필요한 근거·통과 기준·실패 처리를 현재 작업과 연결한다. 검사마다 새 문서·사용자 승인·리뷰어를 추가하지 않는다. 명세→계획→실제 결과와 관련 참조의 일치도 확인한다.

## Findings

리뷰 지적 사항에는 안정된 ID·심각도·대상 버전/위치·위반 요구 또는 구체적 위험·발생 조건·근거·영향·해결 조건을 담는다. 가설과 입증된 결함을 구분한다. 취향·테스트 부재만으로 필수 수정을 요구하지 않는다. 기능·일반화 추가 요구에는 [현재 필요에 맞는 해법](code-quality.md#proportional-solutions)을 적용한다.

| Severity | Meaning |
| --- | --- |
| `Critical` | 심각한 보안·데이터 손실 또는 핵심 동작·설계 성립을 깨는 문제. 관련 진행 차단 |
| `Important` | 요구 누락·계약 모순·유의미한 회귀·필수 검증 공백. 해당 단계 통과 전 해결 |
| `Minor` | 수용 기준을 해치지 않는 국소 개선. 기록 후 진행 가능 |

| Verdict | Meaning |
| --- | --- |
| `Pass` | 필수 리뷰를 수행했고 진행을 막는 미해결 문제가 없음 |
| `Changes required` | 근거로 확인된 필수 수정이 남음 |
| `Inconclusive` | 자료·접근·검증 부족으로 판정 불가 |

필수 검토를 못 했다면 지적 사항이 없어도 Pass가 아니다. 입증된 결함과 근거 공백이 함께 있으면 둘 다 기록한다. 판정은 사용자 승인·병합·배포 권한을 부여하지 않는다.

## Report and Closure

작업의 `reviews/<review-id>.md`에 대상·실제 범위·근거·실행 검사·지적 사항·미검증·판정 이유를 보존한다. 메인 에이전트는 유효한 문제를 수정에 연결하고 오탐에는 반증을 남긴다. 해결 여부가 다투어지면 추가 근거나 별도 리뷰로 판단한다.

재검토는 기존 지적 사항의 ID·해결 조건과 수정 영향 범위를 확인한다. 수정하지 않은 호출자·문서도 영향을 받으면 포함한다. 새 리뷰 보고를 만들되 기존 보고·문제별 수정 횟수를 보존하고 근거 없이 전체 리뷰를 다시 열지 않는다.
