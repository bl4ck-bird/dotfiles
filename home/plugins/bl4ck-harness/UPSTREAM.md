## 대응과 의도적인 차이

Superpowers의 `using-superpowers`는 `using-bl4ck-harness`으로, 나머지 계승 스킬은 `bl4ck-harness-` 접두사로 대응한다. 원본의 사용 지침과 비자명한 판단을 한글로 재작성했으며 원본 파일 전체를 배포하지 않는다.

| 원본 영역 | 계승 | 변경 |
| --- | --- | --- |
| 브레인스토밍·계획 | 요구 탐색·대안·수용·실행 분해 | 제품·전체 설계·로드맵·변경 명세 분리, 전체 코드와 고정 시간 단위 제거 |
| 하위 에이전트 실행 | 파일 인계, 동일 형태 작업 묶기, 구현자 재개, 한 리뷰어의 두 판정, 범위 재검토, 중첩 위임 금지, 이벤트 대기 | 변경별 영속 상태, 중요 결함의 자동 수용 금지, 권한 있는 병행만 허용, 기록 자동 삭제 제거 |
| 실행 모델 선택 | 작업 위험과 통합 난이도에 따른 선택 | 현재 호스트의 실제 모델만 사용, 소스의 고정 최상위 모델 규칙과 코드 전사 전제 제거 |
| 격리·전달 | 실제 변경과 검증 확인, 미추적 파일 보호 | Git 없는 프로젝트 지원, 격리·커밋·외부 전달 권한을 각각 확인 |
| 도메인 모델링 | 용어 충돌·구체적 사례·코드 대조·즉시 갱신·선별적 결정 기록 | `.harness/design/domain.md`에서 관계·상태·불변식까지 유지 |
| 모듈 설계 | 작은 인터페이스·국소 변경·관측 가능한 계약 | 특정 영문 용어의 일괄 강제 없이 프로젝트 용어 존중 |
| 명세·작업 분해 | 계약 중심 명세, 검증 가능한 수직 단위, 넓은 변경의 단계적 호환 이행 | 공개 트래커와 AGENTS 설정 주입을 필수로 하지 않음 |

`bl4ck-harness-design`, `bl4ck-harness-roadmap`, `bl4ck-harness-spec`, `bl4ck-harness-review` 및 공통 문서·상태 정책은 사용자 요구에 맞춰 추가했다. `docs/` 경로, 공개 트래커 게시, 전체 코드가 들어가는 계획, 무조건적인 워크트리·커밋·문서 삭제는 원본 그대로 이식하지 않았다.

원본 보조 스크립트는 영문 Task 제목·계획 파일명·`.superpowers/` 경로·커밋 기반 리뷰를 전제한다. 이를 그대로 복사하지 않고 파일 인계 원칙을 한글 계약으로 유지했다. 새 기록 도구는 초기화·구조 검사·대상 사본 보존에 한정하며 에이전트 실행 엔진이 아니다.

시각 모형 서버·텔레메트리·다른 런타임 설치기·원본 유지보수 스크립트는 이 패키지의 필수 기능이 아니므로 포함하지 않는다. 필요할 때 호스트의 시각화·브라우저 도구를 사용한다. 원본과 성능·호환성이 동일하다고 주장하지 않는다.

업데이트할 때 이 커밋과 새 릴리스의 스킬·참조·실행 계약을 비교하고 영향을 받는 부분만 반영한다. 원본 변경을 자동 병합하지 않는다.

## 최신판에서 선택적으로 반영한 내용

2026년 9월 22일 v6.4.1과 대조했다. 명세가 암시하지만 검증이 빠뜨린 실패 입력을 해당 작업에 연결하고, 인라인 실행은 연속 구현 후 전체 독립 리뷰를 기본으로 한다. 공유 계약·고위험 변경은 계획한 중간 검토를 적용하며 수정 후 영향 검증과 재리뷰는 유지한다. 미판정 동작의 이유와 프로젝트 필수 검사에서 발견한 기존 실패도 보고한다. 실제 작성된 계획 승인과 기존 실행 방식 선택을 존중한다.

별도 Review Focus 파일·고정 다섯 항목, task-start/task-done 원장, 중첩 컨트롤러, 수정 뒤 재리뷰 생략은 이식하지 않았다. Markdown 상태와 현재 기록 부담을 유지한다. 원본과 비용·속도가 같다고 주장하지 않는다.
