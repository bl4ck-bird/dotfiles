# 완료 주장 전 검증

무엇이 완료됐다는 주장인지 범위를 먼저 정한다. 해당 수용 기준·필수 검사·실제 결과물·환경을 확인하고 필요한 명령이나 사용자 흐름을 실행한다. 전체 출력을 읽어 실패·누락·경고의 영향을 판단한다.

다른 버전의 통과, 실행 예정, 테스트 파일 존재, 에이전트의 자신감은 현재 완료 근거가 아니다. 기존 결과를 재사용할 때도 대상과 영향 범위가 동일한지 확인한다. 실행하지 못한 검증은 이유와 범위를 밝힌다.

구현 완료·테스트 통과·독립 검토·사용자 수용·전달 완료를 구분한다. 남은 필수 작업이 있으면 완료로 표현하지 않는다. 결과를 evidence와 상태에 연결하고 최종 보고에는 필요한 근거와 실제 한계를 담는다.
