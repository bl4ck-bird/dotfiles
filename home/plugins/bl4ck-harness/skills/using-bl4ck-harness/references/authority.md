# 권한과 검토

## 승인 범위

사용자의 명시적 요청과 대화에서 이미 합의한 목표·범위·제약을 읽는다. 문서의 승인 표시는 실제 사용자 발언과 대상 버전으로 뒷받침되어야 한다. 검토 통과, 설치, 프로젝트 활성화는 구현·외부 전달 승인과 다르다.

중요한 제품 방향·공유 설계·명세·계획은 실제 내용을 제시하고 독립 검토와 사용자 검토를 거친다. 사용자가 해당 내용과 실행을 이미 승인했다면 다시 승인받지 않는다. 명세와 계획을 축약해 한 번에 검토할 수 있다. 향후 단계의 문서가 없다는 이유로 현재 단계의 검토를 막지 않는다.

승인된 실행의 일상적인 구현 선택은 담당자가 결정한다. 제품 계약·공유 경계·수용 기준·권한을 바꾸는 판단은 영향받는 부분만 다시 검토한다. 문서 분량·파일 수·취향만으로 사용자 결정을 요구하지 않는다.

## 수행 경계

코드 변경 승인을 커밋·푸시·PR·병합·배포·전역 설치 권한으로 확대하지 않는다. 사용자와 정한 전달 지점까지만 수행한다. 패키지 설치·프로젝트 부트스트랩도 승인 범위에 포함되는지 확인한다. 비밀정보를 읽어 보고서에 복사하지 않는다.

새 작업 공간을 만들 필요는 실제 병행 충돌·격리 요구로 판단한다. 사용자의 기존 변경·브랜치·미추적 파일을 보존한다. 파괴적인 정리·히스토리 재작성은 구체적으로 승인된 대상에만 수행한다.

## 독립 검토

작성자와 다른 에이전트가 실제 대상과 근거를 읽어 검토한다. 적합한 위임 도구와 권한이 없으면 자기 검토를 독립 검토로 표시하지 말고 해당 검토가 미완료임을 알린다. 스킬 존재만으로 호스트의 위임 제한을 우회하지 않는다.

규칙 예외에는 사용자 승인, 대상, 이유, 위험, 보완 검증과 종료 조건이 필요하다. 예외는 보안·비밀정보·권한 경계를 해제하지 않는다. 수정 횟수 소진이나 모델 변경도 예외 승인이 아니다.
