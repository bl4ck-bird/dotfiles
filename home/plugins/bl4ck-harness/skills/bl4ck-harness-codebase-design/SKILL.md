# 모듈과 코드 구조 설계

작은 인터페이스로 충분한 동작을 제공하고 복잡성을 내부에 모으는 모듈을 설계한다. 인터페이스는 타입뿐 아니라 호출 순서·오류·설정·성능·불변식을 포함한다. 모듈은 함수·클래스·패키지 등 현재 문제에 맞는 단위다.

## 판단 기준

- 호출자가 내부를 모르고 올바르게 사용할 수 있는가?
- 하나의 변경이 여러 호출자에게 같은 지식과 수정을 요구하는가?
- 책임·의존 방향·공유 데이터 소유권이 명확한가?
- 실제 복잡성을 줄이는 경계인가, 단순 위임 계층만 늘리는가?
- 내부 구현 대신 외부 계약을 검증할 수 있는 경계가 있는가?

기존 패턴과 호출 흐름부터 확인한다. 책임이 분명한 작은 파일을 선호하되 줄 수나 폴더 개수로 품질을 판단하지 않는다. 관련 요구를 해결하는 데 필요한 개선만 제안한다. 새 인터페이스·플러그인 구조·저장소 계층은 실제 중복이나 경계 보호가 필요할 때 만든다.

대안과 선택 이유를 설계 문서에 기록한다. 모든 이름을 한 용어로 강제하지 않고 도메인과 기존 코드에서 의미가 정확한 이름을 사용한다. 구현된 전체 코드 구조의 사본을 만들지 않는다.
