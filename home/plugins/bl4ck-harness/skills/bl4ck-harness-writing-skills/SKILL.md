# 스킬 작성과 개선

해결할 실제 실패·사용자 요청·적용 범위를 확인한다. 기존 스킬과 공통 기준의 책임을 읽고 한 규칙의 기준을 여러 곳에 복제하지 않는다. 이름·설명은 언제 선택해야 하는지 구체적으로 쓰고 일반 작업을 과하게 끌어들이지 않는다.

스킬 본문은 목적·핵심 판단·진행 조건·필수 참조를 담는다. 특정 단계에서만 필요한 상세 지침은 참조로 분리하고 읽을 시점을 연결한다. 빈 폴더·매뉴얼·예시를 자동으로 늘리지 않는다. 파일을 옮겨 분량만 줄이지 말고 불필요한 규칙을 제거한다.

새로운 스킬·참조·템플릿은 한글로 작성하며 기계 식별자와 원문 계약은 보존한다. 원본에서 가져온 내용의 커밋·대응·변경 이유와 저작권 고지를 유지한다.

정적 검사로 이름·메타데이터·참조·설정 형식을 확인한다. 의미 있는 변경은 현실적인 요청과 최소 자료를 다른 에이전트에게 주어 새 프로젝트·기존 변경·재개·실패 조건의 행동을 확인한다. 예상 답을 평가자에게 미리 주지 않는다. 실제 미충족 동작만 수정하고, 검증하지 않은 호스트 자동 로딩이나 성능을 보장하지 않는다.
