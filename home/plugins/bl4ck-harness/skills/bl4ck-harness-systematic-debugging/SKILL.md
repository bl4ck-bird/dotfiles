# 체계적인 원인 조사

## 재현과 경계

오류·입력·환경·변경 시점·기대 동작을 수집한다. 실제 실행 결과를 읽고 가장 작은 재현을 만든다. 재현되지 않는 현상은 추측 수정 대신 필요한 관측을 정한다. 관련 계층 사이의 입력·출력을 추적하며 비밀정보는 출력하지 않는다.

## 가설 검증

정상 동작과 실패 동작의 차이를 찾는다. 한 번에 하나의 원인 가설을 세우고 최소 실험으로 확인한다. 임의 대기 시간·광범위한 재시도·여러 변경을 동시에 넣어 원인을 가리지 않는다. 비동기 작업은 관측 가능한 조건과 제한 시간으로 확인한다.

반복 수정이 실패하면 시도한 접근과 반증을 읽고 가설을 갱신한다. 공통 구조가 원인이면 관련 설계로 돌아간다. 세션·모델 교체로 수정 횟수를 초기화하지 않는다.

## 수정과 반환

원인과 범위를 근거로 설명하고 수용 계약을 보존하는 최소 수정을 수행한다. 새로운 범위·권한이 필요하면 그 부분만 확인한다. 재현을 회귀 검증으로 보호하고 관련 호출자·실패/복구 경로를 확인한다. 조사·결과·미검증은 해당 변경의 evidence에 남기고 상태를 메인에게 반환한다.
