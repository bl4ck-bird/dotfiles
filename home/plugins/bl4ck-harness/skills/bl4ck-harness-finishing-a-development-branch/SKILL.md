# 통합 완료와 전달

`bl4ck-harness-verification-before-completion`을 적용한다. 전체 목표·수용 기준·필수 검사·독립 검토·남은 지적과 실제 결과를 대조한다. 작업별 통과가 전체 연결 동작을 증명하는지 확인한다.

## 기준 문서 갱신

검증된 변경의 계약만 `specs/`에 반영한다. 제품·설계의 목표 중 실제로 구현된 부분을 구분하고, 실행 중 확정된 중요한 결정은 담당 기준 문서에 반영한다. 향후 기능·검증하지 못한 동작을 현재 사실로 기록하지 않는다. 참조 문서·공개 API 안내가 영향을 받으면 함께 갱신한다.

에이전트 상세 기록은 `.harness/`에 남긴다. `docs/`에는 실제 사용자·개발자에게 필요한 동작·운영·변경 이유만 제품 관점으로 작성한다. 내부 ID·배정·리뷰 지시·비공개 경로가 제품 변경·브랜치·커밋·PR·생성물에 섞이지 않았는지 확인한다.

## 전달과 상태

사용자가 정한 전달 지점까지 수행한다. 코드 작성 승인만 있으면 커밋·푸시·PR·병합·배포를 자동 수행하지 않는다. 전달 권한이 있으면 실제 대상·환경을 확인하고 수행 결과를 검증한다. 승인된 공개 메시지는 내부 작업 기록을 제거하고 변경·이유·검증·한계를 설명한다.

완료 조건을 충족한 변경의 status를 완료로 갱신하고 CURRENT와 ROADMAP 요약을 맞춘다. 기록을 사용하는 변경은 공통 상태 기준에 따라 `check`로 형식·완료 모순·참조를 확인한다. 구현만 끝났으면 검토·수용·전달의 남은 상태를 적는다. 기록·사본·검증 근거를 자동 삭제하지 않는다. 워크트리 제거는 사용자 승인과 유일한 근거·미추적 파일 보존을 확인한 뒤 수행한다.

최종 보고에는 결과·실제 검증·남은 문제·전달 상태와 필요한 파일 링크를 담는다.
