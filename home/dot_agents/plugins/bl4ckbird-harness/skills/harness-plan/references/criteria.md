# Planning Criteria

## Work Units

| Unit | Completion |
| --- | --- |
| 슬라이스 | 연결된 동작 검증과 필수 독립 리뷰 통과 |
| 태스크 | 배정된 구현·필요한 검증 완료 |
| 실행 순서 | 태스크 안의 한 행동의 결과 확인 |

테스트·구현·정리마다 별도 태스크를 만들지 않는다. 같은 맥락·검증은 묶고 책임·의존성 차이가 배정을 정당화할 때 나눈다. 재현·테스트만 요청된 태스크는 그 결과까지만 완료로 본다.

## Coverage

각 수용 기준을 슬라이스·태스크·검증에 연결한다. 태스크에는 실제/제안 경로·행동·소비/제공 계약·선행 결과·검증과 기대 결과를 포함한다. 개별 구성 요소의 검사뿐 아니라 실제 호출·데이터 흐름 연결과 최종 통합 검증을 계획한다.

계속 유지할 공통 제약은 영향받는 각 슬라이스·태스크에서 참조하고 필요한 검증에 연결한다. 앞선 성과에서 한 번 검증했다는 이유로 후속 작업의 준수 의무를 지우지 않는다.

동작 테스트가 유효한 경우 실패→구현→통과→정리를 적용한다. 문서·기계적 변경에 인위적인 실패 단계를 만들지 않는다. 충분한 기존 검증과 프로젝트 필수 검사를 유지한다.

## Execution Authority

합의한 결과물 전달 지점, 코드·기록 위치, 격리·정리 범위, 환경·권한·외부 의존성, 사용자만 판단할 조건을 명시한다. 기본 수정·호출 복구 한도와 별도 합의한 시간·토큰·금액 한도를 구분한다.

계획 자체의 승인 표시를 근거로 삼지 않는다. 독립 리뷰 후 사용자 승인을 실제 명세·계획 버전과 연결한다. 승인 범위의 내부 선택과 태스크 진행에는 반복 확인을 요구하지 않는다.
