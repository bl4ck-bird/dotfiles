# Identifier Allocation

사람이 탐색하는 작업·슬라이스·결정·리뷰·진단·호출·시도 ID는 `YYYY-MM-DD-NNN-<description>`을 쓴다. 작업 폴더명과 `work_id`는 같다.

발급에는 [기록 도구](record-tools.md)의 `reserve`를 사용한다. 원문 문서에만 있는 기존 ID도 메인이 대조하고, 예약한 ID를 이후 기록에 그대로 연결한다.

- 프로젝트 시간대, 없으면 사용자 시간대로 생성 날짜를 정하고 시간대를 기록한다.
- 종류와 상위 범위 안에서 당일 이미 할당한 최대 번호 다음을 사용한다. 완료·중단한 번호도 재사용하지 않는다. 새 날짜는 `001`부터, 최소 세 자리로 쓰고 999를 넘으면 숫자로 정렬한다.
- 짧고 동작을 알아볼 수 있는 이름을 쓴다. 영어는 소문자·하이픈, 프로젝트 규칙에 따른 한글도 가능하다. 경로 구분자·상위 경로 이동·플랫폼 금지 문자는 거부한다.
- 메인 에이전트가 기존 기록과 충돌을 확인해 할당한다. 재개·순서 변경·제목 수정으로 ID를 바꾸지 않는다. 같은 문제를 다시 다루면 기존 시도 횟수도 유지한다.
- 기존 경로를 덮어쓰지 않고 생성한다. 충돌하면 원인을 대조한 뒤 다음 번호를 선택한다. 새 리뷰 라운드·별도 결정은 새 ID를, 독립적으로 계획할 새 범위는 새 작업을 만든다. 같은 작업·문제의 재개는 기존 ID를 유지한다.
- 호스트가 발급한 에이전트·세션·호출 ID는 별도 필드에 원문 그대로 연결한다. 이 값도 내부 정보다.

프로젝트의 작업·결정은 프로젝트 범위, 슬라이스·리뷰·진단·호출·시도는 해당 작업과 기록 종류 범위에서 번호를 할당한다. ID 문자열만으로 전역 고유성을 가정하지 않는다. 태스크 내부 실행 순서에는 별도 ID를 만들지 않는다.
