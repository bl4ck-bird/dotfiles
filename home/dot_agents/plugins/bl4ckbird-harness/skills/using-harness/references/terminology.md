# Terminology

| Term | Usage |
| --- | --- |
| 메인 에이전트 | 진행·배정·결과 확인·공유 상태 갱신을 맡는 에이전트 |
| 구현 에이전트 | 배정된 태스크를 구현·검증하는 서브에이전트 |
| 리뷰어 | 작성자와 분리되어 대상을 수정하지 않고 검토하는 에이전트. 자기 리뷰 보고는 작성 가능 |
| 시스템 설계 | 프로젝트 전체의 책임·경계·공유 인터페이스·제약 |
| 상세 명세 | 가까운 작업의 동작·오류·데이터·수용 기준. 식별자는 `spec` 유지 |
| 구현 계획 | 상세 명세를 구현·통합·검증하는 작업 순서. 식별자는 `plan` 유지 |
| 계약 | 입력·출력·오류·상태·호환성 등 지켜야 할 구체적인 동작 보장. 일반 작업 지침은 규칙·기준·절차로 표현 |
| 수용 기준 | 요청한 결과가 충족됐는지 판단할 조건. 사용자의 실행 허가인 승인과 구분 |
| 근거 / 검증 | 근거는 판단을 뒷받침하는 자료, 검증은 확인 행위와 그 결과 |
| 기준 문서 | 현재 규칙·정의를 관리하는 문서. 과거 승인 대상 사본과 구분 |
| 검토 대상 버전 | 실제 리뷰한 문서 내용 또는 코드 상태 |
| 리뷰 지적 사항 | 근거·영향·해결 조건을 갖춘 문제. 기계 필드 `finding`은 유지 |
| 작업 단계 | 탐색·설계·계획·실행 등 개발 흐름의 현재 위치 |
| 슬라이스 / 태스크 | 리뷰 가능한 연결 동작 / 한 구현 에이전트의 응집된 작업 |
| 실행 순서 | 태스크 안의 테스트·구현·정리 행동. 별도 ID·파일·배정 없음 |
| 결과물 전달 | 합의한 로컬 결과·PR·병합·배포 등 최종 지점에 도달하는 작업. 배포 자체와 동의어가 아님 |

대화에서 같은 개념의 표기를 일관되게 쓰되 코드·API 이름을 임의로 바꾸지 않는다. 프로젝트 도메인의 용어가 다르면 의미와 적용 범위를 확인하고 명시적으로 연결한다.
