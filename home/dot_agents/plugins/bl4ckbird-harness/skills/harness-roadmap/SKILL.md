# Roadmap Planning

## Inputs

- 비전·요구·승인된 설계·공통 제약·남은 위험을 읽는다. 갱신 작업이면 진행 중 작업과 완료 근거도 확인한다.
- [로드맵 기준](references/criteria.md)을 적용한다. 제품·구조의 새로운 결정은 해당 단계로 돌려보낸다.
- 작성 전 [작성 규칙](../using-harness/references/authoring.md)과 [문서 관리·저장 경계](../using-harness/references/storage.md)를 읽는다.

## Planning and Updates

문서를 새로 작성할 때 [템플릿](assets/roadmap.md)을 사용한다. 안내를 실제 내용으로 채우고 무관한 항목은 제거한다. 기존 문서는 필요한 부분만 갱신한다.

- 사용자에게 확인 가능한 성과별로 범위·요구·완료 조건·선행 의존성·위험·열린 질문을 정한다.
- 가치·의존성·위험 검증 시점으로 순서를 판단한다. 성과 없는 기반 작업을 먼저 쌓거나 먼 작업까지 구현 태스크로 나누지 않는다.
- `.harness/roadmap/index.md`에 성과·순서·의존 관계·다음 대상을 둔다. 독립적인 상세가 필요할 때만 개별 마일스톤 문서로 분리한다.
- 실제 기한은 제약으로, 추정은 근거와 불확실성이 있는 예상으로 기록한다. 순서 변경으로 항목 식별자를 바꾸지 않는다.

| Change | Action |
| --- | --- |
| 검증된 진행 사실·문서 연결 | 근거를 확인해 갱신 |
| 성과 추가·제외·우선순위·수용 범위 | 이유·전후 차이·후속 영향을 사용자와 검토 |
| 승인 범위의 실행 태스크 순서 조정 | 실행 계획의 재량으로 처리 |

- 진행은 작업 기록을 참조하고 검증 로그·재시도 횟수를 복제하지 않는다. 개별 작업 완료만으로 통합 동작이나 필수 수용 기준까지 완료됐다고 판단하지 않는다.

## Review and Handoff

- [검토·승인 대상](../using-harness/references/approvals.md)을 보존하고 `harness-review`에 요구 누락·숨은 의존성·순환·위험 해소 순서·완료 조건의 검토를 요청한다.
- 필수 리뷰 후 사용자 승인을 받으면 다음 성과의 범위·요구·설계·선행 조건·수용 근거·미결정을 `harness-spec`에 넘긴다.
- 로드맵 승인은 성과와 순서의 승인이다. 구현에는 해당 상세 명세와 실행 계획의 검토·승인이 필요하다.
- `CURRENT.md`를 갱신하고 실제 완료 사실은 `harness-finish`의 문서 동기화와 연결한다.
