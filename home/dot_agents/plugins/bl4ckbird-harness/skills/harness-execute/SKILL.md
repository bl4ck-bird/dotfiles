# Plan Execution

## Entry and Recovery

- [실행 규칙](references/runtime.md)을 읽고 명세·계획의 승인 대상, 실제 코드, 선행 작업, 권한·환경을 확인한다.
- [승인 적용](../using-harness/references/approvals.md)과 [실행 복원](references/runtime.md)을 적용한다. 실행 종료가 불확실하면 충돌할 작업을 보류하고, 남은 작업만 이어 간다.
- 메인 에이전트가 배정·검증·공유 상태를 관리한다. 구현 에이전트는 배정 범위에서 시작하며 추가 에이전트를 직접 호출하거나 공유 완료 상태를 확정하지 않는다.

## Assignments

- [슬라이스·태스크 경계](../harness-plan/references/criteria.md)에 따라 태스크 하나의 테스트·구현·검증을 한 구현 에이전트에게 맡긴다. 새 태스크는 새 구현 에이전트, 리뷰 수정은 유효한 맥락이 남은 기존 구현 에이전트를 기본으로 한다.
- 배정 전 [상태·기록 게시](references/runtime.md), [모델 선택](../harness-review/references/models.md), [호출 복구](references/resources.md)을 읽는다. 호출 의도와 필요한 시도 기록을 먼저 보존한다.
- 격리·병행 작업이 필요하면 [워크트리·공유 자원](references/worktrees.md)을 확인한다. 코드 경로와 작업 기록의 기준 경로를 구분한다.
- 구현 에이전트에게 다음 입력을 전달한다. 메인 에이전트가 읽은 규칙을 구현 에이전트도 안다고 가정하지 않는다.

| Input | Content |
| --- | --- |
| 대상·권한 | 태스크·슬라이스, 승인 명세·계획, 변경 범위·선택 범위 |
| 맥락 | 선행 결과, 관련 계약·불변식, 코드·문서 경로 |
| 검증 | 실제 명령·기대 결과·적용 게이트 |
| 규칙 | [코드 품질·주석](../harness-review/references/code-quality.md), [작성 규칙](../using-harness/references/authoring.md), [저장·노출 경계](../using-harness/references/storage.md) |
| 반환 | 보고 위치, 중단·질문 조건. 수정 배정은 지적 사항·가설·남은 한도 포함 |

## Implementation and Verification

- [테스트 품질](../harness-review/references/test-quality.md)을 적용한다. 동작 테스트가 유효한 태스크는 실패→구현→통과→정리를 이어가고, 문서·기계적 변경이나 충분한 기존 검증이 있는 작업은 계획의 적절한 검증을 수행한다. 기대값을 깨진 구현에 맞추거나 필수 검증을 약화하지 않는다.
- 구현 에이전트는 `Completed` / `Needs input` / `Blocked`와 실제 변경·검증·미검증·남은 문제를 보고한다. 재현·테스트만 요청받은 작업의 완료는 결함 수정 완료와 구분한다.
- 메인 에이전트는 실제 변경과 결과를 확인한 뒤 근거·처리 결과를 보존하고 공유 상태를 갱신한다. 구현 에이전트의 완료 문구나 명령 종료 코드만으로 통과시키지 않는다.
- 보고가 없거나 근거가 부족하면 필요한 결과를 복구·검증한다. 유효한 검증을 의례적으로 반복하지 않는다.

## Execution Loop

| State | Next Action |
| --- | --- |
| 태스크 완료, 슬라이스 작업 남음 | 선행 조건을 충족한 다음 태스크 실행 |
| 슬라이스 동작·통합 검증 준비됨 | `harness-review`에 독립 검토 배정 |
| 유효한 리뷰 지적 사항 | 승인 범위에서 수정 후 해결 조건·영향 범위 재검토 |
| 원인 불명·반복 실패 | `harness-diagnose`로 조사 |
| 중요한 계약·범위·권한 변경 필요 | 영향받는 실행을 보류하고 사용자와 설계 검토 |
| 계획 구현·필수 리뷰 완료 | `harness-finish`로 통합 수용·전달 확인 |

- 구현 에이전트의 질문과 리뷰 지적 사항은 기존 계약·근거로 먼저 판단한다. 이견에는 반증이나 추가 리뷰를 확보한다. 승인 범위의 구현·수정·검증을 매번 사용자에게 재확인하지 않는다.
- [재시도 한도](references/retries.md)를 적용하고 에이전트·모델·세션·최종 검증으로 카운터를 초기화하지 않는다. 한도 소진을 결함 수용이나 완료로 처리하지 않는다.
- 필수 리뷰를 통과하지 않은 작업에 의존하는 실행은 시작하지 않는다. 충돌하지 않는 독립 작업은 유효한 권한 안에서 계속한다.
- 상태·다음 행동이 바뀌면 `CURRENT.md`를 갱신한다. 태스크마다 자동 커밋하지 않고 합의된 전달 범위를 따른다.
