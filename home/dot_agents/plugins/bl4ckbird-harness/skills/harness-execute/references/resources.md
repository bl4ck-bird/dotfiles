# Calls and Recovery

## Before Dispatch

현재 작업·단계·대상·권한, 미완료 배정, [수정 한도](retries.md), 허용 모델을 확인하고 [실행 기록](runtime.md)을 남긴다. 구현 전 리뷰에는 현재 검토 권한만 필요하며 미래 구현 계획·수정 시도를 만들지 않는다.

## Call Recovery

- 최초 호출 이후 같은 논리적 배정의 복구 호출은 최대 두 번이다. 같은 모델 재시도와 대체 모델 호출을 함께 센다.
- 실행 여부가 불확실하면 [현재 실행 상태](runtime.md)를 확인하고 충돌할 호출을 반복하지 않는다.
- 인증·권한·설정 문제는 원인을 해결한다. 실제 수정이 검증에 실패했다면 호출 오류로 분류해 수정 횟수를 지우지 않는다.
- 대체는 [모델 선택](../../harness-review/references/models.md)을 따른다. 적격 독립 리뷰어가 없으면 `Inconclusive`로 기록하고 해당 검토 조건을 유지한다.

## Stopping

수정·호출 한도 소진, 진전 없는 반복, 필수 판단 공백에는 영향받는 새 배정을 멈추고 실제 상태·근거·남은 검증·다음 행동을 남긴다. 한도 안의 승인된 실행은 반복 확인하지 않는다. 한도 소진은 완료나 결함 수용이 아니다.

사용자 중단 요청이나 필요한 실행 취소 시에도 종료 요청과 실제 종료를 구분하고 부분 변경을 확인한다.
