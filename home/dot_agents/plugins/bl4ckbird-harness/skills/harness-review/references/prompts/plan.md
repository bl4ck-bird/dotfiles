# Implementation Plan Review

## Inputs

승인된 상세 명세·관련 설계·구현 계획·실제 코드/검증 환경·허용 재량. 공통 입력·판정·보고는 [리뷰 기준](../contract.md)을 따른다.

## Review Questions

- 모든 수용 기준이 슬라이스·태스크·검증으로 연결되는가?
- 실제 호출·데이터 흐름을 연결하고 통합 결과를 검증할 작업이 있는가?
- 태스크가 응집된 구현·검증 단위이며 의존성·공유 자원·병행 충돌을 고려했는가?
- 실재 경로·명령과 새 제안을 구분하고 필요한 환경·권한·결과물 전달 지점을 정했는가?
- 테스트가 실제 오구현을 탐지하고 계약에서 기대값을 얻으며 기존 검증 대비 가치가 있는가?
- 문서·기계적 작업에 무의미한 TDD를 강제하거나 중요한 설계·필수 검증을 구현자에게 미루지 않았는가?

## Scope

완성 코드를 계획에 요구하지 않는다. 기본 수정·호출 복구 한도와 별도 합의한 자원 상한을 구분한다.
