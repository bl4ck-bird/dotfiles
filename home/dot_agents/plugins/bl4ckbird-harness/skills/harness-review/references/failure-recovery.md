# Failure and Recovery

외부 호출·영속 상태·중복 실행·중단·권한 변화에서 중요한 불변식이나 수용 기준을 깨뜨릴 시나리오를 선택한다. 모든 분기마다 문서·테스트를 만들지 않는다.

## Questions

- 어떤 실제 사건이 어느 경계에서 정상 흐름을 끊는가?
- 어느 구성 요소가 처리하고 무엇을 보존해야 하는가?
- 실패 시 이미 바뀐 상태와 남은 상태는 무엇인가? 응답 유실과 실제 실패를 구분할 수 있는가?
- 재시도·취소·재개가 중복 효과·손실·불일치를 만들지 않는가?
- 사용자·호출자가 보는 결과와 가능한 다음 행동이 계약과 일치하는가?
- 설계에서는 어떤 확인이 필요하며, 구현 결과에서는 어떤 실제 근거가 있는가?

시스템 설계는 책임·보존 조건, 상세 명세는 정확한 동작, 계획은 검증 방법, 구현 리뷰·완료는 실제 결과를 확인한다. 승인되지 않은 복구 동작을 리뷰 과정에서 임의로 정하지 않는다. 지적 사항에는 구체적인 검증 공백과 영향을 기록한다.
