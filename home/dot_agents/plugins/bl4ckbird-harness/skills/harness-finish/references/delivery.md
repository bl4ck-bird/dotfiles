# Acceptance, Delivery, and Cleanup

## Completion

명세·계획의 수용 기준과 실제 통합 결과, 필수 리뷰·검증·사용자 확인을 대조한다. 유효한 기존 근거는 재사용하되 통합·관련 변경이 만든 차이는 검증한다. 완료는 합의한 지점에 상대적이며 로컬·PR·병합·배포를 모두 강제하는 순서가 아니다.

## Documentation Sync

영향받은 현재 구조·인터페이스·제약, 결정의 실제 적용 위치, 로드맵의 수용 조건·의존성, 사용자 문서·현재 상태를 갱신한다. 미구현 부분과 검증 공백을 유지하고 과거 승인 대상·리뷰를 덮어쓰지 않는다. 제품 문서에 내부 작업 ID나 기록 경로를 넣지 않는다.

코드와 다른 문서를 무조건 코드에 맞추지 않는다. 승인된 동작의 결함인지 요구 변경인지 먼저 판단한다. 확인된 사실 갱신은 재승인 없이 가능하나 범위·우선순위·수용 기준 변경은 관련 검토가 필요하다.

## Authorized Delivery

합의한 권한 안에서 커밋·푸시·PR·병합·배포를 수행하고 실제 상태를 확인한다. 권한이 없으면 검토 가능한 결과를 먼저 준비한 뒤 필요한 승인만 요청한다. 실패·시간 초과의 외부 작업은 실제 결과를 확인하기 전 반복하지 않는다.

배포가 전달 지점이면 실행 전에 서비스 정상 동작 확인 방법과 실패 시 복구 조건·권한·절차를 합의한 계획에서 확인한다. 배포 후 실제 환경에서 확인하며 명령 성공만으로 정상 동작을 판정하지 않는다. 확인에 실패하면 합의된 조건·권한 안에서 복구하고 그 결과도 확인한다. 범위를 벗어나는 복구는 실제 상태와 필요한 조치를 제시하고 해당 권한을 요청한다. 배포 권한만으로 임의의 롤백·데이터 복원을 허용하지 않는다.

검증·문서·사용자 수용·전달·정리 결과를 구분한다. 사용자 확인이 필요 없는 경우 의례적인 최종 승인을 추가하지 않는다. 필요한 조건이 남으면 완료로 선언하지 않는다.

계획에서 식별한 실제 기기·시각 판단 등 필수 사용자 확인이 남으면 작동하는 결과를 먼저 준비한다. 기존 완료 보고에 접근 위치·재현 행동·기대 결과·환경 제약을 담아 구체적으로 확인할 수 있게 한다. 단순히 확인 대기 상태만 반환하지 않는다.

## Cleanup

작업 공간 정리 전 [보존과 정리 근거](retention.md)의 자격 조건·내용 대조·중단 복구를 읽는다.

대상의 생성/재사용 이력·소유·현재 실행·고유 변경·보존 근거·정리 권한을 확인한다. 기존 범위에 포함된 정리는 다시 묻지 않되 사용자 변경·유일한 근거·다른 작업 자원을 함께 제거하지 않는다.

정리 의도를 먼저 기록하고 대상 워크트리 밖에서 실행한다. 직접 만든 Git 워크트리는 `git worktree remove`로 제거한다. 호스트가 관리하는 작업 공간은 해당 관리 절차를 따른다. 정상 제거가 거절되면 원인을 조사하며 `--force`·`git clean`·재귀 삭제로 자동 전환하지 않는다. 로컬 브랜치 삭제는 워크트리 제거와 별도로 승인된 정리 범위에 포함되어야 한다.

기록의 기준 위치를 보존하고 작업 공간만 승인 범위에서 정리한다. 대상별 제거·보존·실패와 이유를 남긴다. 중단 후 실제 존재·보존 상태를 확인하며 삭제를 맹목적으로 재실행하지 않는다. 원격 브랜치·외부 자원은 별도 권한을 확인한다.
