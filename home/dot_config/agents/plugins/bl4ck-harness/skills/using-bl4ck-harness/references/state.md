# 현재 상태와 장기 작업 재개

## 하나의 실행 상태

실행을 조정하는 메인 에이전트가 `changes/<변경명>/status.md`를 갱신한다. 구현자·리뷰어는 자기 결과만 보고한다. 상태는 Markdown 한 곳에 두며 JSON 상태 파일과 배정·시도·결과별 이력 파일을 추가하지 않는다. `CURRENT.md`에는 활성 변경의 status 링크·미해결 사항·다음 행동만 적고 작업 표를 복제하지 않는다. 기록 도구가 검사할 링크는 아래처럼 인라인 형식으로 쓴다. 참조형 링크는 검사하지 않는다.

```markdown
[변경](changes/<변경명>/status.md)
``` 로드맵은 성과 수준으로 요약한다.

## 최소 형식

진행 기록이 필요한 변경에만 아래 여섯 항목을 쓴다. 제목·항목명과 작업 표의 두 열은 검사 계약이므로 유지한다. 단계와 설명은 자유롭게 작성한다. 설명할 내용이 없으면 `없음`으로 적는다.

```markdown
# 폴더 가져오기

## 현재 상태
- 단계: 구현
- 상태: 진행 중

## 작업
| 작업 | 상태 |
| --- | --- |
| 폴더 읽기 | 완료 |
| 중복 처리 | 진행 중 |
| 통합 검증 | 미착수 |

## 확인할 실행
없음

## 차단 사항
없음

## 검증
폴더 읽기 테스트 통과. 중복 처리와 통합 검증은 아직 실행하지 않음.

## 다음 행동
중복 처리 구현과 관련 테스트를 마무리한다.
```

전체와 작업의 상태는 `미착수`, `진행 중`, `검토 중`, `보류`, `완료`, `실행 확인 필요` 중 하나다. 아직 작업을 나누지 않은 탐색·설계에서는 작업 표 대신 `없음`으로 쓸 수 있다. 전체 완료 시에는 수행한 작업이 있고 모두 완료여야 하며, 확인할 실행과 차단 사항은 정확히 `없음`이어야 한다. 표는 작업·상태 두 열과 구분선을 사용하며 이름 안의 세로줄은 `\|`로 쓴다.

실제 배정이나 백그라운드 실행이 있을 때만 확인할 실행에 대상·호스트 식별자·확인할 내용을 적는다. 종료와 결과를 대조한 항목은 지우고 아무것도 남지 않으면 `없음`으로 쓴다. 짧은 검증은 명령·환경·결과를 본문에 적고 긴 출력은 기존 evidence에 연결한다. 승인·리뷰는 기존 근거를 참조한다. 수정 반복이 생겼을 때만 같은 문서에 누적 횟수와 최근 시도·미해결 문제를 짧게 유지한다. 매 명령·호출의 이력 파일을 만들거나 실제 검증 없이 완료 표시를 맞추지 않는다.

## 갱신과 검사

작업 상태가 바뀌거나 차단·미확인 실행이 생겼을 때, 세션 마무리·전체 완료 보고 전에 갱신한다. 호출 식별자를 알게 되면 현재 실행 항목에 보완한다. 모든 편집·명령마다 기록하거나 검사하지 않는다.

기록을 사용하는 변경의 세션 마무리·완료 보고 전 [기록 도구](tools.md)의 `check`를 한 번 실행한다. 여섯 항목의 누락, 완료와 미완료 작업의 모순, 완료에 남은 차단·미확인 실행, 문서 참조와 CURRENT의 활성 status 링크를 검사한다. 활성 기록이 없으면 상태 문서를 만들거나 상태 검사를 위한 절차를 추가하지 않는다. 오류가 있으면 실제 근거에 맞춰 해당 부분만 고친다. 기존 다른 형식의 상태 문서도 자동으로 덮어쓰지 않는다.

검사는 CURRENT에 연결된 상태와 `현재 상태` 절의 `상태` 필드로 식별되는 상태 문서를 대상으로 한다. CURRENT에 연결되지 않은 이전 자유형식 상태는 형식 검사를 건너뛰고 그 개수를 알린다. 그 기록의 활성 여부를 추측하지 않으며, 실제로 재개할 때만 CURRENT에 연결하고 필요한 형식을 보완한다. 과거 문서 전체를 일괄 변환하지 않는다.

검사는 파일을 변경하거나 실행을 재생하지 않는다. 임의의 문장으로 적힌 테스트 결과·승인 의미·코드의 최신성·실제 실행 종료는 판정하지 않으며 통과가 기능 완료의 증명은 아니다. 별도 코드 캡처·전체 해시 대조·실행 이력 재구성을 기본 절차로 요구하지 않는다.

## 재개와 보존

CURRENT → 활성 status → 필요한 명세·계획·코드·근거 순으로 읽는다. 기록과 실제 결과가 어긋난 부분만 대조한다. 결과가 있고 상태만 늦었다면 유효성을 확인해 상태만 보완하며 구현을 처음부터 반복하지 않는다.

종료가 불명확한 실행은 관련 호스트·프로세스를 확인할 때까지 충돌할 작업만 보류한다. 시간 경과·연결 단절·중단 요청을 종료 증거로 쓰지 않는다. 세션·모델·담당자가 바뀌어도 알려진 수정 횟수와 미해결 문제를 지우지 않는다.

설계·명세가 바뀌면 영향받는 계획·검증·승인을 재검토하고 관련 근거와 다음 행동을 갱신한다. 필수 검증·리뷰·현재 기준 문서 동기화·합의한 전달 지점이 충족돼야 전체 완료다. Git 제외 기록은 커밋으로 복구되지 않으므로 자동 삭제하지 않는다. 워크트리 정리 전 유일한 근거를 확인하고 승인된 위치에 보존한다.
