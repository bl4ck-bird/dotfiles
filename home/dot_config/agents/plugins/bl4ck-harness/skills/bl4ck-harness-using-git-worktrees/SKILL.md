# Git 작업 공간 격리

실제 Git 루트·브랜치·미커밋/미추적 변경·기존 워크트리를 확인한다. Git이 없는 프로젝트에 작업 공간을 만들기 위해 Git을 초기화하지 않는다. 격리 필요가 없다면 현재 작업 공간을 사용할 수 있다.

사용자 지정 위치·브랜치를 우선한다. 새 브랜치가 필요하면 프로젝트 규칙을 따르고 없으면 제품 목적이 드러나는 이름을 쓴다. 내부 리뷰·슬라이스 ID를 이름에 넣지 않는다. 공유 브랜치 변경 범위와 사용자 변경을 확인한다.

작업 기록이 있는 원 프로젝트와 새 워크트리의 관계를 배정에 명시한다. 메인이 관리하는 기준 기록 경로를 하나로 정하고, 구현자에게 실제 편집 디렉터리와 허용된 보고 경로를 함께 전달한다. 별도 권한이 없는 공유 경로에 쓰지 않는다. 접근할 수 없으면 메인에게 보고를 반환해 기록하게 한다.

프로젝트 필수 설정·기본 검사를 확인한다. 의존 설치는 승인 범위에서만 수행한다. 시작 시 실패한 검증과 기존 문제를 기록한다.

정리는 `bl4ck-harness-finishing-a-development-branch`의 권한·보존 기준을 따른다. 미추적 파일이 있다는 이유로 강제 삭제하거나 작업 공간을 자동 제거하지 않는다.
