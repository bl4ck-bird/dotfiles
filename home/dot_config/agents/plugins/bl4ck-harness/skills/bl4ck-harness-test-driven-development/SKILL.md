# 테스트 기반 개발

승인된 동작과 테스트할 외부 계약을 확인한다. `bl4ck-harness-codebase-design`의 모듈 경계를 활용하고 기존 검증을 우선 재사용한다.

1. 요구를 어기는 실제 구현을 잡을 수 있는 작은 테스트를 작성한다. 버그는 재현 조건을 먼저 확보한다.
2. 테스트를 실행해 의도한 이유로 실패하는지 읽는다. 문법·환경 오류를 동작 실패로 혼동하지 않는다.
3. 요구를 만족하는 최소 구현을 추가한다. 미래 옵션·불필요한 추상화를 넣지 않는다.
4. 관련 테스트를 실행해 통과를 확인한다. 필요한 정리를 수행하고 영향을 받는 검증을 다시 실행한다.

입력과 기대 결과는 명세·불변식·독립 예시로 결정한다. mock 자체를 검증하는 테스트, 구현을 복제한 기대값, 항상 참인 assertion을 만들지 않는다. 실패 검증 없이 이미 코드가 작성됐으면 사용자 변경을 삭제하지 말고 재현 가능한 회귀 검증을 확보하고 검증의 한계를 보고한다.

가독성 수정·문서·링크 같은 비동작 변경에는 무의미한 단위 테스트를 강제하지 않는다. 필요한 구조·형식 검사와 프로젝트 필수 검증은 수행한다.
